## M1 数据采集与规范化（P0，当前阶段）

### 1.1 确定研究范围

- [ ] 确定**一个**研究城市（建议杭州），并写入 `docs/data-dictionary.md`。
- [ ] 确定岗位类别白名单，例如：后端开发、前端开发、算法工程、测试开发、数据分析、大数据开发、运维开发、网络安全、嵌入式开发。
- [ ] 确定筛选标准（发布日期、招聘对象、岗位数量上限/下限、是否包含实习岗）。
- [ ] 确定目标样本量（建议 200～300 条，保证每条都可人工核验）。
- [ ] 确定数据来源网站清单，检查 robots / 使用条款，优先人工收集公开信息。

### 1.2 采集执行

- [ ] 建立采集表格（Excel / 在线表格），字段与 `job_postings` 对齐。
- [ ] 每条记录保留公司名、岗位名、原始薪资文本、学历原文、经验原文、来源链接、采集时间。
- [ ] 每人认领固定数量（如 4 人 × 60 条），避免重复采集。
- [ ] 采集过程中记录截图或链接快照，供报告与答辩核验。
- [ ] 完成后随机抽取 10% 记录人工回访来源链接。

### 1.3 数据清洗

- [ ] 公司名去重（同一企业不同简称合并），保留原始写法到 `description` 或清洗日志。
- [ ] 岗位名称归一到 `job_type` 白名单。
- [ ] 学历统一为：不限 / 大专 / 本科 / 本科及以上 / 硕士 / 硕士及以上 / 博士 / 其他。
- [ ] 经验统一为：不限 / 应届生 / 1年以内 / 1-3年 / 3-5年 / 5年以上 / 其他。
- [ ] 薪资统一为**人民币月薪**：
  - [ ] 年薪 ÷ 12、日薪 × 21.75、时薪 × 174 的换算规则写入文档。
  - [ ] `13薪/14薪` 等保留原始标注，默认按 base 月薪统计并在数据说明中注明。
  - [ ] `x-y K` 统一乘 1000；面议保持 `null`，不得填 0。
  - [ ] 明显异常值（< 2000 或 > 100000）逐条复核。
- [ ] 技能拆分：每条岗位 1～10 个标准词，禁止把整句 JD 塞进 `skills`。
- [ ] 技能同义词合并：如 `springboot` → `Spring Boot`、`mysql数据库` → `MySQL`，扩充 `backend/app/services/skills.py` 词表。
- [ ] 输出 `data/raw/jobs_<city>_<date>.json`，并通过 `python -m scripts.import_sample <file>` 验证。
- [ ] 生成一份数据质量摘要：总条数、缺失率、重复率、各字段分布、异常值清单。

### 1.4 数据验收标准

- [ ] 必填字段（id / company / position / job_type / city）缺失率 0。
- [ ] 薪资有效率 ≥ 90%，且 min ≤ max。
- [ ] 学历、经验不在词表内的值 ≤ 5%，并逐条说明。
- [ ] 同一 id、同一来源链接无重复。
- [ ] 抽样 30 条与原始页面一致。

## 当前风险与待决策

- [ ] **城市与岗位范围未定**：决定数据采集量，必须尽快拍板。
- [ ] **真实数据尚未开始**：这是当前最大风险，优先于任何美化工作。
- [ ] **学历“本科及以上”归类**：单列还是并入本科？统一决定后全站不改。
- [ ] **13/14 薪处理**：按 base 月薪统计，需在数据说明页声明。
- [ ] **技能词表规模**：词表过小会导致“其他”占比高，需在数据清洗阶段补齐。
- [ ] **样本代表性**：结论只能限定在“本次采集的样本”，不能写“杭州市场如何”。
- [ ] **数据版权/隐私**：不采集个人联系方式，不绕过登录或反爬限制。
